# Focus10 — SaaS лендинг + қолданба

Фрилансерлер мен командаларға арналған уақыт/тапсырма басқару өнімі:
конверсияға бағытталған лендинг **және** оның артындағы нақты жұмыс істейтін
қолданба — тіркелу, тапсырма басқару, таймер, апталық есеп.

**Стек:** React 19 (Vite) · Tailwind CSS v4 · React Router · lucide-react ·
Express 5 · **Postgres** (Supabase / Neon / кез келгені)

**Маршруттар:** `/` — лендинг · `/app` — қолданба · `/app/settings` —
параметрлер (соңғы екеуі тек кірген қолданушыға) · қалғаны — 404

## Лендингтегі мәліметтің бәрі шынайы

Бет артында нақты жұмыс істейтін өнім тұрғандықтан, ондағы бірде-бір мәлімет
ойдан шығарылмаған:

| Бұрын | Қазір |
|---|---|
| «12 000+ команда» | Тексеруге болатын фактілер (тегін, CSV, Postgres, 118 тест) |
| Ойдан шығарылған клиент логотиптері | Мүлдем алынып тасталды |
| Аты-жөні жазылған 3 адамның жалған пікірі | «Кімге арналған» сценарийлері — ешкімнің атынан кепілдік берілмейді |
| «14 күн тегін», «кез келген уақытта бас тарт» | Сынақ мерзімі де, жазылым да жоқ — сондай-ақ жазылды |
| Қолмен салынған «өнім скриншоты» | **Қолданбадан алынған нағыз экран суреті** |
| Жоқ мүмкіндіктер бар сияқты | Футердегі «Жоспарда» бағанында **әлі жасалған жоқ** деп ашық жазылған |
| Ешқайда апармайтын 14 footer сілтемесі | Тек шынымен бар сілтемелер |

`public/app-dashboard.png` — қолмен салынған макет емес, жұмыс істеп тұрған
қолданбаның `/app` бетінен headless Chrome арқылы 2x сапада түсірілген нағыз
скриншоты (мысал аккаунттың деректерімен). UI өзгергенде оны қайта түсіру
керек — әйтпесе бет шындықтан ажырап қалады.

## Іске қосу

Дерекқор керек. Екі жолдың бірін таңда.

**А) Ештеңе орнатпай, жергілікті** — PGlite (Postgres-тің WASM нұсқасы):

```bash
npm install
npm run db:local                  # 55432 портында Postgres көтереді
```

Екінші терминалда `.env` файлын жасап (үлгісі — `.env.example`), мынаны қой:

```
DATABASE_URL=postgres://postgres@127.0.0.1:55432/postgres
PG_POOL_MAX=1
```

**Б) Supabase-пен** — Project Settings → Database → Connection string-ті
`.env` ішіндегі `DATABASE_URL`-ға көшір.

Сосын:

```bash
npm run dev      # фронт (5180) + API (3080) қатар қосылады
```

Аш: **http://localhost:5180**

Хат жіберу міндетті емес: `RESEND_API_KEY` қойылмаса, құпиясөзді қалпына
келтіру мен email растау сілтемелері API терминалына жазылады — жергілікті
әзірлеуге сол жеткілікті.

Басқа командалар:

```bash
npm test         # 118 API тесті — нағыз Postgres-ке қарсы (PGlite)
npm run dev:web  # тек Vite
npm run dev:api  # тек Express (node --watch)
npm run build    # dist/ шығады
npm start        # продакшн: Express дайын dist/-ті де, API-ды да береді
npm run lint
```

**Ортаның айнымалылары**

| Айнымалы | Әдепкі | Не үшін |
|---|---|---|
| `DATABASE_URL` | — | **міндетті**, Postgres байланыс жолы |
| `APP_TZ` | `Asia/Almaty` | «бүгін» мен «осы апта» қай белдеумен есептеледі |
| `PORT` | `3080` | API порты |
| `PG_POOL_MAX` | `10` | байланыс пулының өлшемі (PGlite-пен `1` болуы керек) |

> **PGlite туралы.** Ол бір мезгілде бір ғана байланысты ұстайды, сондықтан
> жергілікті әзірлеуде `PG_POOL_MAX=1` қажет. Supabase-те бұл шектеу жоқ.

> **Порт туралы.** Әдепкі 5173-ті басқа жоба иеленіп қалса, Vite үнсіз басқа
> портқа көшеді де, 5173-те бөгде сайт ашылып тұрады. Шатаспау үшін
> [vite.config.js](vite.config.js)-те `strictPort` арқылы 5180 бекітілген —
> порт бос болмаса Vite енді жасырынып көшпей, қатемен тоқтайды. Ол `/api`
> сұраныстарын Express-ке проксилейді, сондықтан браузер үшін бәрі бір origin.

### Күндік жоспар

Тапсырма тізімі «нені істеу керек» дегенді айтады, бірақ «бүгін нені, қанша
уақыт» дегенге жауап бермейді. Соны `server/lib/planner.js` есептейді — таза
функциялар, дерекқорсыз әрі уақытсыз, сондықтан кез келген күнмен тестіленеді.

Қолданушыдан екі нәрсе ғана сұралады:

1. **Не істегің келеді** — тапсырмаға болжалды уақыт (`estimate_minutes`),
   маңыздылық (`priority`: міндетті / керек / болса болды) және мерзім
   (`due_date`) қосылады. Үшеуі де міндетті емес: бос қалса, жоспарлағыш
   әдепкі мәнмен (60 минут, «керек», алдағы 7 күн) жұмыс істей береді.
2. **Бүгін қанша уақытың бар** — таңертең бір рет. Ұсынылатын нұсқалар
   сағатқа қарай есептеледі: сағат 14-те «күні бойы боспын» деген 8 сағат
   емес, кешке дейінгі уақыттың 60%-ы (бос уақыт пен зейін бір нәрсе емес).

Одан кейінгісін жоспар өзі шешеді:

- **қалғаны** = баға − бұрын жазылған уақыт, сондықтан таймерді басқан сайын
  ертеңгі жүктеме азаяды;
- **күндік үлес** = қалғаны ÷ мерзімге дейінгі күн. Бүгінге сол үлес қана
  беріледі — бір күнде бәрін бітіру ешқашан талап етілмейді;
- **кезек**: мерзімі өткендер → мерзімі жақындар → маңыздылығы. Жұмада
  тапсырылатын «міндетті» істің әлі уақыты бар, ал бүгін бітуге тиіс «болса
  болды» істің жоқ;
- **тізімнің ұзындығы уақытқа қарай қысқарады**: 25 минутқа бір ғана іс
  жазылады. Аз уақытқа үш іс жазсақ, үшеуі де басталмайды;
- **уақыт артып қалса** ғана алдағы күндердің жүгі бүгінге тартылады.

«Кеш ояндым, енді бәрі құрыды» деген сезім жоспардың ең басты қарсыласы,
сондықтан аз уақыт айтқаны үшін ешкім жазғырылмайды: 25 минут та жарамды
жауап, жоспар қысқарады да, қалғаны келесі күндерге жайылады. Күн ортасында
жағдай өзгерсе, қайта тіркелуге болады — ескі жоспар ауысады.

Оның есесіне алдағы 7 (және 30) күннің жиынтығы ашық көрсетіледі: қалғаны
қалған күнге сыймаса, «күніне 6 сағаттан» шығатыны бүгін айтылады — мерзімді
жылжытуға да, бір істен бас тартуға да әлі мүмкіндік бар кезде.

### Дерегіңнен шығатын қорытындылар

`/api/reports/insights` — диаграмма көрсетпейтін нәрсені айтады. Соңғы 28
күндегі нақты жазбалардан есептеледі, ешқандай болжам жоқ:

- **ең қауырт үш сағат** — тәулік бойындағы таралудың шыңы (үлесі 30%-дан
  төмен болса, «шың жоқ» деп саналады да, көрсетілмейді);
- **осы апта / өткен апта** салыстырмасы;
- **үзілмеген күндер сериясы** (бүгін әлі жұмыс істемесе, сериясы кешеден
  саналады);
- **ең өнімді апта күні** — тек жұмыс істелген күндер бойынша орташа, әрі ол
  күн кемінде екі рет кездескен болуы керек;
- **әдеттегі сессияның ұзақтығы** (медиана) мен ең ұзағы;
- **10 минутқа жетпей үзілген сессиялардың үлесі** — фокус емес, ауысып
  отырғаны.

Дерек аз болса (3 сессия / 2 күннен кем), сервер сан құрастырмайды: `ready:
false` қайтарады да, қолданба «әлі ерте» деп ашық жазады.

Сөйлемнің өзін клиент құрайды: сервер тек сандарды береді, себебі қазақша
мен ағылшыншада сөйлем құрылымы әртүрлі.

### Аккаунтты қайтару

Ұмытылған құпиясөз — жоғалған аккаунт дегенді білдірмеуі керек:

- **токендер қорда ашық сақталмайды** — тек sha256 хеші жатады, сондықтан
  дерекқорға қол жеткізген адам сілтемені қалпына келтіре алмайды;
- токен **бір реттік**: тексеру мен жою бір `DELETE ... RETURNING`
  сұранысымен жүреді (қатар келген екі сұраныс екеуі де өтіп кетпеуі үшін);
- қалпына келтіру сілтемесі 1 сағат, растау сілтемесі 24 сағат жарамды;
- `/api/auth/forgot` email тіркелген-тіркелмегеніне қарамастан **әрқашан
  204** қайтарады — әйтпесе бұл маршрут «мына адам осында бар ма?» дегенге
  жауап беретін құралға айналар еді;
- құпиясөз ауысқанда **барлық сессия жабылады**;
- email растау — тосқауыл емес, ескерту: расталмаған аккаунт та толық жұмыс
  істейді.

Хат `RESEND_API_KEY` мен `MAIL_FROM` арқылы жіберіледі. Олар қойылмаса, dev
пен тестте сілтеме сервердің консоліне жазылады, ал продакшнда маршрут ашық
түрде 503 қайтарады — жетпейтін хатты күттіргеннен гөрі шындықты айтқан
дұрыс.

### Тегін хостингтегі «ұйқы»

Vercel-де қолданба ұйқыға кетпейді, бірақ суық старт бар: ұзақ тыныштықтан
кейінгі бірінші сұраныс функцияны көтеруге бір-екі секунд жұмсайды. Күту
2,5 секундтан асса, қолданба айналған дөңгелектің орнына себебін жазады
(`WakingLoader`) — түсініктемесіз күту «сайт бұзылған» болып оқылады.

`.github/workflows/keepalive.yml` — Render заманынан қалған: тегін жоспарда
сервер 15 минут белсенсіздіктен кейін ұйықтап, келесі сұраныс оны 30–60
секунд оятатын. Vercel-де оның қажеті жоқ. Репоның `APP_URL` айнымалысы
қойылмаса, workflow бәрібір ештеңе істемей өтеді; мүлдем керек болмаса,
Actions бөлімінен өшіріп қоюға болады.

### Тестер

```bash
npm test
```

118 тест: тіркелу мен валидация, құпиясөздің хештелуі, сессияның мерзімі,
құпиясөзді қалпына келтіру мен email растау (токеннің бір реттігі, мерзімі,
түрін алмастыруға болмайтыны), деректен шығарылатын қорытындылар,
**қолданушылардың бір-бірінен оқшаулануы** (бөтен тапсырманы оқу/өзгерту/жою
және оған таймер қосу мүмкін емес), таймер инварианттары, есеп пен CSV
экрандауы, қауіпсіздік тақырыптары, rate limit.

Тесттер **нағыз Postgres-ке** қарсы жүреді: PGlite — Postgres-тің
WebAssembly-ге компиляцияланған нұсқасы, эмулятор емес. `pg` клиенті оған
продакшндағыдай TCP арқылы қосылады, сондықтан SQL диалектіндегі
айырмашылықтар тестте де көрінеді. Әр тест файлы өз данасын көтереді.

### Қауіпсіздік

- Құпиясөз **scrypt**-пен хештеледі (кездейсоқ salt), салыстыру
  `timingSafeEqual` арқылы.
- Сессия — DB-де сақталатын кездейсоқ 32 байттық токен, **httpOnly** cookie
  ішінде (`sameSite=lax`, продакшнда `secure`). JWT-ден айырмашылығы — сессияны
  сервер жағынан бірден жоюға болады.
- Барлық сұраныс `user_id` бойынша сүзіледі — бөтен адамның тапсырмасын оқу да,
  өзгерту де мүмкін емес.
- `/api/auth/*` — минутына 10 әрекет (rate limit).
- Кіру қатесінде «email табылмады / құпиясөз қате» деп бөлмейміз — қай email
  тіркелгенін сыртқа шығармау үшін.
- «Бір мезгілде бір ғана таймер» шарты қосымша кодта емес, Postgres-тің
  partial unique index-і арқылы бекітілген.
- Email бірегейлігі де индекспен тексеріледі (`lower(email)`) — алдын ала
  SELECT жасасақ, екі сұраныс арасында бәсеке пайда болар еді.
- `DATABASE_URL` кодта да, репозиторийде де жоқ — тек орта айнымалысында.
- Қауіпсіздік тақырыптары: CSP, `X-Frame-Options`, `nosniff`, HSTS
  (продакшнда), `X-Powered-By` өшірілген.
- Құпиясөз ауысқанда барлық сессия жойылады — ұрланған сессия жарамсыз болады.

### Тұрақтылық

- SIGTERM/SIGINT келгенде жүріп жатқан сұраныстар аяқталып, Postgres пулы
  дұрыс жабылады (10 секундтан кейін мәжбүрлеп).
- Дұрыс емес JSON 400, тым үлкен body 413 қайтарады, 500 емес.
- Frontend-те `ErrorBoundary` бар: рендер қатесі ақ экранға айналдырмайды.
- Бет фоннан оралғанда таймер серверден нақтыланады (дрейфке қарсы).

## Тіл жүйесі (Қазақша / English)

Беттің де, қолданбаның да барлық мәтіні екі тілде. Ауыстырғыш navbar-да,
футерде, dashboard тақырыбында, Параметрлерде және 404 бетінде тұр.

**Тіл қалай таңдалады.** Бұрын сақталған таңдау (`localStorage`) → браузердің
тілі (`navigator.languages`) → әдепкі `kk`. Таңдау `lang` cookie-мен серверге
де жетеді, сондықтан API қателері мен CSV тақырыптары сол тілде қайтады.
Сервер cookie болмаса `Accept-Language`-ке қарайды.

**Фронт.** Мәтіндер [src/i18n/locales/](src/i18n/locales/) ішінде — екі
каталогтың құрылымы бірдей (185 кілт). Компонентте:

```jsx
const { t, lang, setLang, formatDuration } = useI18n()

t('dashboard.tasks')                          // жол
t('projects.openCount', { count: 3 })         // «{{count}}» орындалады
t('features.items')                           // массив те қайтады
```

Аудармасы жоқ кілт `kk`-ға қайта оралады, ол да болмаса кілттің өзі көрінеді —
бет ешқашан мәтінсіз қалмайды.

**Бэкенд.** [server/lib/i18n.js](server/lib/i18n.js) — қате мәтіндері, CSV
тақырыптары және жаңа аккаунттың бастапқы деректері. Middleware `express.json()`
дейін жүреді, сондықтан бүлінген JSON туралы қате де аударылады. Маршрутта
`req.t('task.notFound')` деп қолданылады.

**Жаңа тіл қосу.** `src/i18n/locales/`-қа каталог қосып, оны
`src/i18n/messages.js`-тегі `messages` мен `LANGUAGES`-ке тірке; сервер жағында
`server/lib/i18n.js` ішіндегі `messages` мен `LANGUAGES`-ке де сол кодты қос.
Ауыстырғыш тізімді өзі алады, компоненттерді түртудің қажеті жоқ.

**Тілге тәуелді емес дерек.** Жоба мен тапсырма аттары — қолданушының өз
деректері, аударылмайды. Жаңа аккаунттың бастапқы жобасы тіркелген кездегі
тілде құрылады да, кейін тіл ауысса да өзгермейді.

## Деплой

Дерек Postgres-те тұрғандықтан, веб-сервистің файл жүйесі уақытша болса да
ештеңе жоғалмайды — яғни **тегін жоспар жетеді**.

**1. Дерекқор.** [supabase.com](https://supabase.com) → New project → Project
Settings → Database → Connection string. Ол — құпия мән, оны репозиторийге
салуға болмайды.

**2. Хостинг.** [vercel.com](https://vercel.com) → Add New → Project →
`focus10` репосын таңда. Vercel `vercel.json`-ды өзі оқиды, сондықтан build
пен маршруттарды қолмен баптаудың қажеті жоқ. Settings → Environment
Variables бөлімінде екі мән қоясың:

| Айнымалы       | Мәні                                                     |
| -------------- | -------------------------------------------------------- |
| `DATABASE_URL` | Supabase → **Transaction pooler** (порт `6543`) жолы      |
| `CRON_SECRET`  | `openssl rand -hex 32` — cron маршрутын қорғайды          |
| `PG_POOL_MAX`  | `1` (міндетті емес, бірақ ұсынылады — төменде түсіндірме) |

Хат жіберу керек болса, `RESEND_API_KEY` мен `MAIL_FROM` да қосылады.
`APP_URL` қажет емес: Vercel өз доменін `VERCEL_PROJECT_PRODUCTION_URL`
арқылы береді, ал өз домені жалғанғанда ғана оны қолмен қоясың.

Одан кейін әр `git push` сайын Vercel өзі қайта деплой жасайды.

```bash
git push origin main
```

### Serverless-те не өзгереді

Vercel Express серверін тұрақты ұстамайды — әр сұраныс үшін функция оянып,
кейін өшеді. Сондықтан «сервер іске қосылғанда бір рет» істелетін жұмыс
`server/`-дан тыс шығарылды. `server/` коды өзгерген жоқ: `api/index.js`
дәл сол `createApp()`-ты экспорттайды, ал `npm start` арқылы қосымша бұрынғыша
тұрақты сервер болып та жүре береді.

| Не                     | Тұрақты серверде (`npm start`)    | Vercel-де                                        |
| ---------------------- | --------------------------------- | ------------------------------------------------ |
| Схеманы құру           | іске қосылғанда `migrate()`       | build қадамында `npm run db:migrate`             |
| Ескі сессияларды өшіру | сағат сайынғы `setInterval`       | Vercel Cron → `/api/cron/purge` (тәулігіне 1 рет) |
| Фронтті беру           | `express.static('dist')`          | Vercel CDN, функцияға мүлдем соқпайды            |
| Postgres пулы          | бір процесте 10 байланыс          | әр дана 1 байланыс, pooler арқылы                |

**Дерекқор жолы — міндетті түрде pooler.** Supabase-тің тікелей жолы
(порт `5432`) бір уақытта ондаған байланысқа есептелген, ал serverless-те
әр функция данасы өз пулын ашады да, лимит тез бітеді. Transaction pooler
(порт `6543`) дәл осыған арналған. `PG_POOL_MAX=1` сол логиканы аяқтайды.
Қосымша күйге тәуелді сессия параметрлерін қолданбайды (уақыт белдеуі әр
сұранысқа параметр болып беріледі), сондықтан transaction режимі қауіпсіз.

**Cron тәулігіне бір рет.** Vercel-дің тегін жоспарында cron күніне бір рет
қана жүреді — сондықтан `vercel.json`-да `0 3 * * *` тұр. Тазалау тек мерзімі
өткен жазбаларды өшіреді, ал жарамдылық тексерісі сұраныс кезінде бәрібір
жүреді, сондықтан кешігу қауіпсіз.

**Rate limiter әлсірейді.** `server/rateLimit.js` есепті процестің жадында
ұстайды. Тұрақты серверде бұл бір ғана процесс, ал Vercel бір мезгілде
бірнеше дана көтеруі мүмкін — сонда әр дананың өз есебі болады да, нақты
шек `max × дана саны` болып шығады. Brute force-қа тосқауыл болып қалады,
бірақ бұрынғыдай қатаң емес. Қатаң керек болса, есепті ортақ жерге
(Postgres кестесі немесе Redis) көшіру керек.

**Ескерту.** Supabase-тің тегін жобасы ұзақ пайдаланылмаса тоқтатылады,
панельден қайта іске қосуға болады. Vercel-дің функциялары ұйқыға кетпейді,
бірақ суық старт бар — бірінші сұраныс бір-екі секунд ұзақ жүруі мүмкін.

**Render.** `render.yaml` репода қалды: қосымша тұрақты сервер болып та
жүре беретіндіктен, қажет болса Render-ге қайта оралуға болады.
